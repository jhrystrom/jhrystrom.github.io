# jhrystrom.github.io

A static site generated by [`build.py`](build.py) — one Python file, no framework.

## Requirements

`uv` and `just`. Nothing else. Dependencies live in `pyproject.toml` — the three libraries
the site needs under `[project]`, and the check tools under the `dev` group — and `uv.lock`
keeps a local run and a CI run resolving identically.

## Commands

```
just dev      # build, serve on :8000, rebuild on change (--future: show scheduled posts)
just build    # write _site/
just fmt      # format Python and markdown in place
just check    # fail on anything malformed — CI runs exactly this
just test     # fast generator unit tests; no browser needed
just test-layout   # layout checks in Chromium at four viewport widths
just check-links   # verify outbound links still resolve (slow, network-dependent)
```

`just check` includes the unit tests. Layout tests run in a separate CI job; install
Chromium's headless shell once with `uv run playwright install --only-shell chromium`
before running them locally. CI also installs only this headless browser.
They visit every built HTML page at each width, checking overflow and the relevant
typography, spacing, and image geometry during the same visit. Screenshots are saved
to `.layout-screenshots/` only when a page fails. Use
`just test-layout --layout-screenshots` to capture every page for visual review, or
`just test-layout --durations=10` to see timings. Pass pytest flags to either test command.

## Publishing a post

Create `content/posts/YYYY-MM-DD-slug.md`:

```markdown
---
title: "Some title"
date: 2026-09-06
---

Text.
```

Then `just check && git commit && git push`. Pushing to `master` deploys.

`title` and `date` are the only required keys. Optional: `permalink` (pin a URL — otherwise
it's derived as `/posts/<year>/<month>/<slug>/`), `summary` (meta description), `draft: true`
(build it locally, exclude it from the site), and `venue` for talk notes.

A post dated in the future is scheduled: it is left out of the build until that date, and
its `pdf` doesn't have to exist yet. Nothing rebuilds on its own, so push on the day (for a
policy brief, the push that adds the PDF) to make it go live. `just dev --future` previews
scheduled posts; a scheduled PDF that's missing is only a warning there.

Talk notes are the same thing in `content/talks/`. They appear at `/talks/`, not on the
front page or in the feed.

## Publishing a policy brief

Put the PDF in `static/papers/`, then create a post that points at it:

```markdown
---
title: "Some policy brief"
date: 2026-09-06
pdf: /papers/some-policy-brief.pdf
summary: "One line for the feed."
---
```

It is listed under Writing with a `(Policy brief)` tag, and the title links straight to the
PDF, which browsers open in their viewer instead of downloading. No HTML page is built for it,
so a body is optional; the feed shows the body, or the `summary` if there is none.

## Publishing a translated pair

Both files carry three extra keys:

```yaml
lang: da                          # da or en
translation_key: agents-are-here  # identical in both files
original: true                    # exactly one of the pair is true
```

Only the original is listed on the front page and in the feed, with an
`(English available)` link beside it. Both get `hreflang` tags and their own URL.

## Publishing a password-protected page

For a standalone HTML page (e.g. a party FAQ) that should be shared, not public. The page is
encrypted on your machine; only the ciphertext is committed, and the browser decrypts it.

```
$EDITOR private/party.html   # gitignored: back it up, it's the only plaintext copy
just encrypt party           # asks for the password -> content/locked/party.json
just qr party                # private/party-qr.png for the invite
git add content/locked/party.json && git commit && git push
```

It's served at `/p/party/`, never listed, and marked `noindex`. Guests either scan the QR
code (`/p/party/#pw=…`, which fills the password in) or type the password. Capitals and
spaces vs hyphens don't matter. The browser remembers it after the first visit.

- The file must be self-contained: inline CSS and scripts, images as `data:` URIs.
  `just encrypt` warns about anything it loads from this site.
- The ciphertext is public, so the password must hold up to offline guessing: four random
  words (`maple-otter-lantern-quilt`), not a phrase about the party.
- There is no revoking access. Anyone with the invite can open it, and a new password only
  locks future versions; old ciphertext stays in git history.
- After editing the page, run `just encrypt party` again. It asks for the password once and
  refuses one that doesn't open the current version, so a typo can't break the QR codes
  already printed. To change the password on purpose, use
  `just encrypt party --new-password`; old links and QR codes then stop working. `just qr`
  makes the same check.

See `implementation-plans/private-pages.md` for the reasoning.

## What `just check` catches

`build.py --strict` is the validator as well as the generator. It fails on:

- front matter that is missing `title`/`date`, or isn't valid YAML
- **any front-matter key outside the allowed set** — this is what catches `titel:`
- a `date` that isn't a real date, or a `lang` outside `da`/`en`
- a `translation_key` group without exactly one `original: true`, or with two files
  sharing a `lang`
- two pages resolving to the same URL
- an internal link or image that doesn't resolve
- a `pdf` that isn't in `static/papers/`
- an image in `static/images/` or a PDF in `static/papers/` that no page references
- a `content/locked/*.json` with fields other than `salt`, `iv`, `iterations`, `ciphertext`,
  bad base64, fewer than 600,000 iterations, or a name that isn't lowercase-and-hyphens
- nothing under `private/` may be committed (a test fails if it is)

Problems print as `content/posts/foo.md:4: …` so an editor can jump to them.

Deliberately not checked on every run: outbound links. They break for reasons unrelated to
your commit, and a check that fails for reasons you didn't cause is a check you learn to
ignore. Use `just check-links` when you want it.
